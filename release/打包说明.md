# 发行版怎么打

生成物：`iPodWithNeteaseCloudMusic-<版本>-windows-x64.zip`（12 MB 左右）

## 步骤

```bash
# 1. 编译 Release 版界面
export PATH="/c/flutter/bin:$PATH"
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
cd app && flutter build windows --release

# 2. 组装（把 Flutter 产物 + 后端源码 + 启动器放到同一个文件夹）
#    见下面的"结构"一节

# 3. 打 zip
```

## 结构

```
iPodWithNeteaseCloudMusic-v0.1.0-windows-x64/
├── 启动.bat                  ← 用户双击这个（先查依赖，缺什么说清楚）
├── 使用说明.txt              ← UTF-8 BOM + CRLF，记事本才不乱码
├── ipod_manager.exe          ← Flutter Release 构建产物
├── flutter_windows.dll
├── data/                     ← Flutter 资源
├── src/                      ← 后端源码（exe 靠它启动后端）
├── pyproject.toml            ← ★ 必须和 exe 同级：exe 从当前目录往上找它
├── uv.lock
├── tools/
├── LICENSE                   ← MIT 要求随分发附带
├── THIRD_PARTY_NOTICES.md    ← 同上（iOpenPod 的 MIT 许可）
└── README.md
```

## 几个坑

* **exe 必须和 `pyproject.toml` 同级**。桌面端从 `Directory.current` 往上找
  `pyproject.toml`（最多 10 层）来定位后端源码；只把 exe 拷出去会报
  "找不到项目目录"。
* **不要带上 `.venv`**。uv 建的 venv 里烘焙了绝对路径，解压到别的路径会失效；
  而且有 111 MB。让用户首次启动时自己装（约 1 分钟），包里同时留着 `uv.lock`
  保证版本一致。
* **不要带上 `.ncm/`**。那里面有登录 cookie——绝不能进发行包。
* **`.bat` 要写 GBK + CRLF**。UTF-8 的中文 .bat 在 cmd 里会乱码，
  LF 行尾更会直接让 cmd 解析错乱（会把一行拆成几条命令执行）。
  验证方法：`MSYS_NO_PATHCONV=1 cmd /c "启动.bat" 2>&1 | iconv -f gbk -t utf-8`。
* **`.txt` 用 UTF-8 BOM + CRLF**，否则老版本记事本打开是乱码。

* [ ] 后端起来：`curl http://127.0.0.1:8765/api/status` 返回 200

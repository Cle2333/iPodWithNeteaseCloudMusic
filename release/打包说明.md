# 发行版怎么打

生成物：`release/iPodWithNeteaseCloudMusic-<版本>-windows-x64.zip`（约 58 MB）

## 一条命令

```bash
uv run python tools/package_release.py --version 0.2.0
```

它内部会先跑一次完整构建（`tools/build_windows_release.py`），想用现成产物加
`--skip-build`。

## 结构

嵌入 Python 之后，**发行包 = 构建产物 + 几个说明文件**，中间不再有"组装源码"这一步：

```
iPodWithNeteaseCloudMusic-v0.2.0-windows-x64/
├── 启动.bat                  ← 用户双击这个（脚本生成，GBK+CRLF）
├── 使用说明.txt              ← UTF-8 BOM + CRLF，记事本才不乱码
├── ipod_manager.exe
├── Lib/                      ┐
├── site-packages/            │ 嵌入的 Python：运行时 + 依赖 + 后端源码
├── app/                      │ （由 serious_python 的 package/flutter build 两步生成）
├── DLLs/                     │
├── python313.dll 等          ┘
├── data/                     ← Flutter 资源
├── LICENSE                   ← MIT 要求随分发附带
└── THIRD_PARTY_NOTICES.md    ← 同上（含 iOpenPod 的 MIT 许可）
```

对比上一版，**消失了**：`src/`、`pyproject.toml`、`uv.lock`、`tools/`、
以及"首次启动联网装 111 MB 依赖"这一步。

## 构建链（三步强耦合，任何一步单独跑都出坏包）

1. `tools/assemble_python_app.py` —— 把 `src/` 摆成嵌入要的平铺布局
2. `dart run serious_python:main package ...` —— pip 装依赖进 site-packages
3. `flutter build windows --release` —— **原生构建阶段**才把 site-packages 和 app 拷进 bundle

第 2、3 步之间靠三个环境变量传递：`SERIOUS_PYTHON_VERSION` /
`SERIOUS_PYTHON_SITE_PACKAGES` / `SERIOUS_PYTHON_APP`。
这些都由 `tools/build_windows_release.py` 统一设置，**不要手动分两次跑**。

## 几个坑（全是实测踩出来的）

* **三个环境变量必须同一 shell 覆盖第 2、3 步**。只在第 2 步设的后果：
  产物里是另一个 Python 版本的运行时而 site-packages 是本次的，
  而且 site-packages / app **根本不进 bundle**（它们是第 3 步拷进去的）。
* **换 Python 版本必须先 `flutter clean`**。不清会留下别的版本的 `.pyc`，
  症状是 `ImportError: bad magic number in 'string'`——应用能起、Python 全无反应。
* **`flutter clean` 必须排在组装 Python 源码之前**（它会删掉整个 `app/build/`）。
* **Windows 没开"开发者模式"时 Flutter 建不了插件符号链接**，构建直接失败。
  `tools/fix_plugin_symlinks.py` 用 junction（不需要管理员权限）绕过。
  注意 `flutter pub get` 本身就会因这个返回非零失败——它该做的事在软链之前
  就做完了，所以要"允许失败 → 补 junction → 再跑一次"。
* **路径一律用 `C:/` 形式**。MSYS 的 `/c/...` 交给 Windows 原生程序会被当成
  `C:\c\...`，pip 装到不存在的路径，而构建**照样"成功"**。
* **`.bat` 要写 GBK + CRLF**。UTF-8 的中文 .bat 在 cmd 里会乱码，
  LF 行尾更会直接让 cmd 解析错乱。
* **不要带上 `.ncm/`**。那里面有登录 cookie——绝不能进发行包。

## 验证清单（打完包一定要过一遍）

```bash
uv run python tools/verify_embedded_release.py --exe <路径>/ipod_manager.exe
```

* [ ] 用 **PowerShell / 资源管理器**解压到**别的路径**
      （MSYS 的 `unzip` 不认 UTF-8 标志位，会把中文文件名解乱——那是 unzip 的问题，不是包的问题）
* [ ] `启动.bat` 双击能起（中文不乱码）
* [ ] 全程**不需要 uv**、不需要联网初始化
* [ ] 后端起来：`curl http://127.0.0.1:8765/api/status` 返回 200
* [ ] 数据落在 `%APPDATA%\com.example\ipod_manager\data\.ncm\`，**不在当前目录**
* [ ] 登录态还在（从旧版升级的话要先把旧 `.ncm\` 拷过去，见 `使用说明.txt`）
* [ ] 插上 iPod → 顶栏显示设备名 + 剩余容量
* [ ] 退出程序后 8765 端口被释放（嵌入模式下后端随进程退出）

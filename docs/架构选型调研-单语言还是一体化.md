# 架构选型调研：Flutter + Python 要不要改成一体

> 结论先说：**真正的痛点不是"两种语言"，而是"两种语言之间隔着一个需要现场安装的运行时"。**
> 这两件事可以分开解决，代价差一个数量级。

---

## 零、结论已落地（2026-09-20 补）

选了**方案 A（`serious_python`）**并做完了。这份文档保留当时的判断依据，
下面是**实际做出来的结果**，供以后回看：

### 做成了什么

Python 运行时 + 依赖 + 后端源码全部进了 `ipod_manager.exe` 那个目录，
跑在**同一进程**的一条线程里。发行包不再需要 uv、不再需要联网初始化、
没有子进程（也就没有孤儿进程和端口残留）。

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 用户要装什么 | uv（+ 有网才能首启） | **什么都不用装** |
| 首次启动 | 联网装 111 MB 依赖，约 1 分钟 | 无 |
| 进程数 | 2（界面 + 后端子进程） | 1 |
| 发行 zip | 12.1 MB | 57.6 MB |
| 解压后体积 | 29 MB exe + 111 MB venv | 153.5 MB（全含） |

### 关键验证（都是实测，不是推理）

- `numpy` / `Pillow` / `pycryptodome` 这些**带原生扩展**的包在嵌入环境里
  能装、能 import、**能真干活**（AES 出结果、生成真 JPEG）——
  桌面用真 CPython + 常规 pip wheel，不受 iOS/Android 那套预编译配方限制
- `uvicorn` 能在**非主线程**里起服务（原本最大的未知风险：信号处理器）
- 产物**自包含**：拷到别的路径、把打包时的开发目录改名，照样跑

### 现在这份文档里没兑现的

**第 5 项（4,300 行 HTTP 管道）还在。** 方案 A 只解决了 1–4，正如本文档当初的判断：
它是"交付问题"不是"语言问题"，而消掉第 5 项要重写 5,500 行界面（方案 B/Flet）。

另外，**"从网易云下载"仍然需要用户装 node** —— 网易云 API（`api-enhanced`）
是个 Node 项目，不在这个仓库里，pip 装不了。要彻底去掉它有三条路：
把 node 也打进包（+100 MB 上下）、或者用 Python 重写那 9 个用到的接口
（要自己实现网易云的加密，并承担接口变动风险）。**尚未决定**。

## 一、先把"不优雅"拆开

现在这一套里，让人不舒服的其实是 5 件独立的事。混在一起讨论就会得出"必须重写"的错误结论：

| # | 问题 | 严重度 | 能不能单独解决 |
| --- | --- | --- | --- |
| 1 | **发行要用户先装 uv + 首启下载 111 MB 依赖** | 🔴 高 | ✅ 能 |
| 2 | **两个进程要管生命周期**（自动拉起、杀整棵树、端口冲突） | 🟠 中 | ✅ 能 |
| 3 | **exe 和源码绑死**（"不要只把 exe 拷出去"） | 🟠 中 | ✅ 能 |
| 4 | **要维护两套工具链**（Flutter SDK + uv/Python） | 🟡 低（只影响你） | ✅ 能 |
| 5 | **HTTP 接口 + 33 个镜像模型**（约 4,300 行管道） | 🟡 低 | ⚠️ 只有换单语言才能消掉 |

**关键判断**：1–4 是"运行时/交付"问题，第 5 项是"语言"问题。
而且第 5 项恰恰是**最不值钱**的一项——一个定义清楚的本地 HTTP API 是可以被测、被单独跑、被独立调试的。
为了消掉 4,300 行管道去重写 5,500 行界面，未必划算。

### 规模账（实测）

  app/lib 纯界面约      5,495 行

## 二、方案清单（都查过实际数据，不是听说）

### 方案 A：`serious_python` —— 把 Python 运行时嵌进 Flutter 应用

**原理**：Flutter 插件，把**真的 CPython**（3.12/3.13/3.14）+ 你的 Python 代码 + `__pypackages__` 一起打进 app 包。
应用启动时在**同一个进程的后台 isolat/线程**里跑你的 `main.py`，界面通过 localhost/内存通道和它说话。

**实测数据**
* 版本 v4.7.0，2026-09-09 发布（11 天前）· GitHub ⭐324 · Apache-2.0 · 由 Flet 团队维护
* **平台支持里 Windows 是 ✅**（iOS/Android/macOS/Linux/Windows 全支持）
* 捆绑的是真 CPython，不是 Pyodide（Pyodide 只用于 Web 目标）
* 官方 README 原话：*"Flutter app is not directly calling Python functions or modules, but instead communicating with Python environment via some API"* —— **边界还在，只是搬进了同一个进程**

**解决什么**：1、2、3、4 全解决。
**不解决**：第 5 项（语言仍然是两种）。

**改造量**：**小**。
- Python 代码：0 行改动
- Dart 界面：0 行改动
- `backend.dart` 的"找 uv / 找 pyproject.toml / 起子进程 / 杀进程树"整段（446 行）换成一次 `SeriousPython.run()`
- 加一个打包步骤：`dart run serious_python:main package src -p Windows`
- 发行包变成一个自包含文件夹，**不再需要用户装 uv**

**风险**
* ⚠️ 原生扩展（numpy / Pillow / pycryptodome）要按平台装进 `__pypackages__`——桌面平台是真 CPython，理论可行，**必须实测**
* ⚠️ 包体积会从 29 MB 涨到约 100–130 MB（换来"零依赖"）
* ⚠️ 项目只有 324 star，但由 Flet 团队（16.9k star）维护，不是孤儿

---

### 方案 B：Flet 1.0 —— 界面也用 Python 写

**原理**：Python 写界面，底层仍然是 Flutter 渲染（Flet 自带 Flutter 客户端）。
桌面应用 = 一个 Python 进程 + 内嵌的 Flutter 渲染器。

**实测数据**
* Flet ⭐16,958 · Apache-2.0 · 最后推送 2026-09-18（2 天前）· 已发布 **1.0.0**
* `flet-desktop` v1.0.0
* 控件清单实拉过仓库：**163 个**，其中这个应用需要的全都有
  `datatable` ✅ `textfield` ✅ **`context_menu`** ✅ `alert_dialog` ✅ `list_view` ✅
  `search_bar` ✅ `selection_area` ✅ `checkbox` ✅ `progress_bar` ✅ `tabs` ✅
  `menu_bar` / `popup_menu_button` / `submenu_button` ✅ `reorderable_list_view` ✅ `keyboard_listener` ✅
* `flet build windows` 直接出桌面包

**解决什么**：1–5 **全解决**，只剩一种语言。
**改造量**：**大**——重写约 5,495 行界面，同时删掉 4,291 行管道。
**之后的总量**：约 35,000 行 Python（内核 28k + 逻辑 7k）+ 一套 Python 工具链。

**风险**
* ⚠️ 界面要**重新做一遍**，包括那些调了很久的细节（状态徽标、右键菜单、多选操作条、日志面板、分页）
* ⚠️ Flet 1.0 刚发布，API 还可能动；出问题时要自己啃 Flet 的坑
* ⚠️ Flet 是"高层控件"风格：`datatable` 给的是基础表格，要做出你现在那种"每行带状态徽标 + 复选框 + 右键"的列表，得用 `Row`/`Container` 自己拼——**可做，但不会比 Dart 省多少行**

---

### 方案 C：PySide6（Python + Qt）—— 走传统桌面路线

**实测数据**
* PySide6 v6.11.2（2026-08-18）· 许可 **LGPL-3.0**
* `PySide6-Essentials` Windows wheel **73 MB**（元包只 1 MB，主体在这里）→ 装完 + Qt 插件约 200–250 MB

**优点**：Qt 二十多年，控件最全、行为最稳、原生性能；`pyside6-deploy` 官方打包。
**缺点**：界面风格跟现在的 Flutter 完全不同，等于**重做设计**；体积最大；LGPL 有合规注意点。
**改造量**：大（重写界面）+ 设计重做。

---

### 方案 D：只把后端"冻结"成 exe（PyInstaller / Nuitka）

**原理**：不改架构，把 `ipod_web` + 依赖冻成一个 exe，Flutter 启动它。

**解决什么**：1、4（不再要 uv/venv）。
**不解决**：2、3、5——**仍然是两个进程**，仍然要管端口和杀进程树。

**改造量**：最小（只改 `backend.dart` 的定位逻辑）。
**风险**：PyInstaller 打包 numpy/Pillow/pycryptodome 有经典坑（hidden imports、DLL 收集）；体积约 80 MB；启动比 venv 慢。

**这条适合"今晚就想让用户不用装 uv"**，但它治标。

---

### 方案 E：干脆不要桌面框架 —— 做成"本地 Web 应用"

**原理**：后端保持 FastAPI，界面写成浏览器页面，启动时打开默认浏览器。
**优点**：后端**零改动**；不需要 Flutter/打包；跨平台天然。
**缺点**：失去原生应用的一切（文件对话框、右键菜单体验、单窗口感、启动速度）；用户会看到一个浏览器标签页。
**改造量**：中（前端重写，但 HTML/JS 比 Flutter 轻）。

**值得考虑的理由**：你的需求是"简易前端"，而且真正的重活在 Python 侧。如果哪天觉得"桌面框架"本身就是负担，这是最省事的方向。

---

### 已排除：把内核重写成 Rust / Go

查了注册表（实测）：

| crate | 下载量 | 说明 |
| --- | --- | --- |
| `libopod-rs` v0.1.0 | **21** | "Safe Rust library for mounted iPods" —— 玩具级 |
| `ithmb-core` v1.9.10 | 283 | 只管 .ithmb 缩略图编解码 |
| `itl-rs` | 174 | 是 iTunes **Library.itl**，不是 iPod 的 iTunesDB |

**没有可用的 Rust/Go 内核。** 而且 `iopenpod` 那 27,979 行里装着 HASH58 密钥派生、七种 chunk 的精确布局、FAT32 刷盘——这是**用几次"数据库损坏、用户几百首歌没了"换来的**。
重写它 = 拿已经验证过的东西去赌，收益仅仅是"少一种语言"。**不建议。**

## 四、建议

**分两步走，先拿确定收益，再决定要不要动界面。**

### 第一步（建议现在做）：方案 A，`serious_python`

* 收益：发行体验从"装 uv + 等 111 MB"变成"解压双击"；`backend.dart` 那 446 行进程管理整段删掉
* 代价：**Python 和 Dart 业务代码一行不改**，只是换一层宿主
* 风险可控：先花半天做**可行性验证**（把 numpy/Pillow/pycryptodome 塞进 Windows 的 `__pypackages__`，确认能 import）
* 失败也不亏：验证不成，回退就是现在的启动方式，代码没动过

### 第二步（想做"真一体"时再评估）：方案 B，Flet

* 只有当你确认"长期维护两种语言"本身就是成本时才值得
* 那时内核、逻辑、测试（约 35,000 行 + 11,000 行测试）**全都不用动**，只重写界面
* 建议先在 Flet 上复刻**一个页面**（比如「iPod 音乐管理」），对比"Flet 拼列表"和"Dart 拼列表"的实际体感再决定

### 不建议

* ❌ Rust/Go 重写内核（无可用库，风险极高，收益仅"少一种语言"）
* ❌ 现在就把界面全部重写（v0.1.0 刚发布、测试全绿、真机验证过——此时动界面是最差的时机）
